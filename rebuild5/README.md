# HAL Desk 5 — independent rebuild track

Status: **ongoing Android 5.0 alpha development, not a completed application or release-ready APK**. Existing 4.6 remains untouched on main.

## Alpha branch identity
- The working Android branch is **5.0.0-alpha.1**, versionCode **32**, while `main` stays on installed release **4.6.0**, versionCode 31.
- The APK remains unsigned until verified CI, Android device/backup migration QA, and original-certificate signing. The same `in.smkt.haldesk` ID and schema-4 SQLite ledger are mandatory.
- Native status reporting, Gradle, npm package/lock, build output filenames, release-identity checks and CI artifact labels share this alpha identity. Do **not** use a new signing certificate or uninstall the installed app.

## Release invariants
- Android application ID `in.smkt.haldesk`, Android 8.0+ and original signing certificate.
- Keep real SQLite schema-4 ledger and original Keystore alias compatible; never overwrite it from PAPER.
- Read-only Upstox Analytics Token, separate NSE research, no order placement.
- Never infer option settlement at an earlier expiry from a later simulated spot.
- Missing quotes, marks, contract metadata or timestamps remain missing.
- New engines must be tested against independently calculated examples and real device QA.

## Implemented on this branch (first vertical slice)
- `android/app/src/main/assets/risk5.js`: strict civil-date validation, lot-to-share conversion, protective-put coverage through expiry, dated protection ladder, explicit per-expiry hypothetical settlement P&L, and mark-to-mark incremental risk.
- `android/app/src/main/assets/quant5.js`: seeded, reproducible illustrative lognormal spot-scenario distribution; accepts a supplied portfolio-pricing callback, refuses missing values.
- `android/app/src/main/assets/backtest5.js`: independent daily-bar SMA-cross research engine; next-bar-open PAPER fills only after completed close signals, explicit two-sided fee/slippage inputs, marked unrealised versus closed gains, drawdown tracking and descriptive 20/50 SMA + realised-volatility regime.
- `android/app/src/main/assets/hedge5.js`: independently audits eligible protective-put replacement scenarios produced by the provider-aware hedge engine; whole-lot units, gross purchase, old-put bid proceeds, signed net cash requirement, worst sampled loss, actual futures expiry gap and like-for-like current-vs-replacement scenario comparability. Model-only; no trading.
- `android/app/src/main/assets/lenses5.js`: local six-perspective evidence readiness map for Technical, F&O, Fundamentals, News, Market Context and Position Risk; explicitly marks stale/missing evidence. This local map does not call Gemini or send the real portfolio anywhere.
- `android/app/src/main/assets/quality5.js`: independent quote provenance/contract-identity reconciliation. Contradictory same-clock provider prices are withheld, while mismatched lot sizes/expiries/strikes retain conflict metadata through the finance engine so even manually entered marks cannot bypass a contract mismatch. Source integrity counts are visible in Data Health.
- `android/app/src/main/assets/continuity5.js`: independently checks successive provider snapshots before they enter the market store. Older provider clocks cannot masquerade as fresh, identical quote/trade clocks with contradictory LTPs are quarantined, and later cached or failed observations cannot clear the quarantine. Exact-key contract identity conflicts persist until re-verification or market cache reset; no real trading book is changed. The Data Health panel displays continuity incidents and Today withholds daily-change headlines during integrity failures.
- `android/tests/continuity5.test.js`, expanded `quality5.test.js` / `data4.test.js`, and browser UI checks cover old/future/missing timestamps, same-clock conflicts, cache mislabeling, cross-feed repair rules, identity mismatches and preservation of the actual book.
- `android/app/src/main/assets/migrate5.js`: QA-only, read-only schema-4 upgrade compatibility check. It rejects loss or mutation of positions, journal fees, lifetime history, private notes and risk limits, while allowing old broker-confirmation flags to be reset for fresh verification. The report contains only changed section names/counts, not the user's private financial or journal data.
- Backup replacement preview now compares the current and incoming books before any save: removed/modified open legs, journal closes and fees, imported historical rows, notes, bookmarks, checkpoints, cumulative charge statements and booked gross/net totals. If any recorded data or booked totals would be lost or changed, an explicit typed `REPLACE` confirmation is required on top of the checkbox. This remains a full replacement, **not** an automatic merge. 
- The app commits changes to its view state, scenario caches, and AI consent context **only after** the SQLite book save reports success. A failed native save cannot silently clear locally displayed calculations or alter the persisted saved book; the user can retry after resolving storage errors.
- `android/app/src/main/assets/portfolio5.js`: read-only lifetime accounting audit. Independently reconciles per-leg units/marks, booked gross P&L, cumulative charge statements, later fees, manual/stale/expired marks and funding versus settlement cash. Withholds net and loss-recovery figures if any required mark or financial invariant fails. Exposes a booked recovery requirement without implying future returns.
- `android/app/src/main/assets/expiry5.js`: deterministic Android-offline expiry agenda for actual open futures and puts, with independently dated quantity gaps, broker-reconciliation prompts, market-calendar limitations and conditional manual funding/reserve checks. No exchange cutoff inference, auto trades or future hedge assumption.
- `android/app/src/main/assets/reconcile5.js`: explicit broker-reported completed-close accounting preview (whole-lot quantity, entry/exit economics, gross/net booked delta, incremental fees and cumulative charge coverage) that intentionally returns no writable book or broker command; after review, the user must separately record an actual close.
- `android/app/src/main/assets/path5.js`: an independently reconciled read-only scenario path for long futures and protective puts with separate earlier option and later futures expiry assumptions. Reports each date's gross put/future economics, cumulative gross and charge-adjusted net, option intrinsic and paid premium, plus uncovered futures units **after** each expiry. Cash debit/credit, physical-delivery amounts and futures daily variation-margin path remain `null` (unavailable), not estimates or spendable cash.
- `android/tests/path5.test.js` and the Risk Playwright check verify earlier-settlement completeness, full gross/net reconciliation, no invented broker cash, immutable inputs and strict actual-book contract limits.
- `android/tests/reconcile5.test.js` plus UI/browser and `engine4.test.js` regressions: zero-price put expiry versus positive-only futures close, partial futures closes, immutable book, older cumulative charges and future-date/refusal checks.
- `android/tests/expiry5.test.js`: checks recorded November/December coverage transitions, expiry-day and after-expiry states, partial futures closes, standalone long puts, unknown/stale funding and the preserved book. The Today and Risk browser regression confirms the saved book is not modified.
- `android/tests/release5.test.js`: release-identity regression for Android 8 minimum, strict app package preservation, versionCode upgrade, source/lockfile version, original certificate and security flags.
- `android/tests/portfolio5.test.js`: tests closed October puts, partial futures closes, cumulative lifetime fee coverage, additional later fees, missing marks, expired contracts, corrupted totals and half-paise rounding. `ui4.test.js` covers the audited Performance screen and unchanged saved book.
- `android/tests/migrate5.test.js`: synthetic closed-put, fee, multi-expiry book, confirmation reset, malformed backup and no-mutation acceptance tests. Expanded replacement-impact tests cover removed or edited completed-trade IDs, fees, private notes, cumulative charge coverage and immutable source objects. A browser regression checks typed confirmation and injected native disk-save failure.
- `android/tests/hedge5.test.js`, `lenses5.test.js` and Playwright AI-panel review checks: accounting reconciliation, missing comparisons, net cash credits, expiry gap and no unintended AI network calls.
- `android/tests/backtest5.test.js` plus Playwright coverage: rejects invalid/missing candles, same-bar look-ahead and invalid window assumptions; confirms the real trade ledger is never modified.
- `android/app/src/main/assets/ui4.js`: Today and Performance use separately audited saved-book P&L and withholding safeguards. Today and Risk include a date-driven expiry and settlement review even when live quotes are unavailable. Those screens also offer a non-persisting broker-close reconciliation preview; only the existing Book transaction editor records actual closes. Risk tab shows the protection ladder, read-only multiple-expiry settlement input, and hypothetical lifetime net using actual recorded closed gross P&L and costs. Stress tab can simulate additional P&L relative to complete current marks using user-specified annual stock volatility. Technicals → Backtest provides a long-only cash-equity reference using verified completed daily candles. Position → Find a hedge → Inspect comparison displays the audited cash and expiry comparison, and AI Desk shows a local six-perspective evidence map without a Gemini request.
- `android/scripts/build-assets.js`: includes the independently authored risk, quant, backtest, hedge, evidence-readiness and quote-quality modules in the pinned esbuild/Chrome 61 WebView bundle, subject to asset hash checks.
- `android/tests/risk5.test.js`, `quant5.test.js`, `quality5.test.js`, `migrate5.test.js`, existing `data4.test.js`, and additions to `ui4.test.js`: finance, source-conflict, manual-mark bypass, and real-book isolation regression tests; included in `npm test` and `npm run test:ui`.
- `rebuild5/risk-core.mjs`: compatibility re-export from the Android source of truth. No duplicate financial implementation.

## Verification and limitations
- Run `cd android && npm ci && npm test && npm run test:ui`. GitHub Actions also executes native Java/Android tests, lint and an unsigned candidate build. Inspect the PR checks for the latest commit before claiming pass.
- Current CI limitation: recent GitHub Actions jobs have failed before runner assignment (no steps executed), even on retry. An earlier run passed the native and browser suite. Selected data/quality (45), migration (8) and portfolio (11) tests passed independently in an isolated JavaScript harness (64/64), and 15 static alpha-release invariants passed. The new risk/expiry tests passed 32/32 in the same lightweight environment. Engine/expiry/close-preview tests (127/127) passed in an independent JavaScript harness after adding the new broker-close preview. No Android or Playwright pass is claimed for the new commits. The lightweight harness does **not** replace `node --test`, full GitHub CI or real-device verification.
- The current branch is **not** a cleanly reimplemented application yet. It is an isolated, compatible vertical slice in preparation for further modular replacement. Existing 4.6 remains on `main`.
- It has **not** been installed on a physical phone, authenticated against real Upstox quotes or signed with the original certificate.
- Monte Carlo fractions are **conditional model samples**, not real-world loss probabilities, historical backtests, guarantees or entry signals.
- The multi-expiry calculator needs explicit settlement values for every option/futures expiry. It is not a substitute for physical-settlement funding/margin calculations, actual broker account records or commission reconciliation.
